# BTC 100배·진입 5% 모의 자동매매 워커 v0.2

실제 돈으로 주문하지 않는 모의 운영 프로그램입니다. Bitget 공개 시세와 봉을 GET으로만 읽습니다. API 키, 계좌 접근, 실제 주문 기능은 없으며 실거래 모드로 전환하는 옵션도 없습니다. 서버 생성·상시 운영은 별도 비용 승인 전에는 시작하지 않습니다.

## 구현한 전략

- BTCUSDT 롱 전용, 교차 100배·최초 진입당 지갑 잔고 5%, 초기 가상자산 $1,000.
- 완료된 해당 시간봉 Wilder RSI(14) ≤ 30과 Hong Pick 피보 빗각 지지선의 위→아래 접촉을 동시에 확인합니다. 기존 지표 소스 및 240봉 채널 탐색을 재사용하며 진입 후 채널 기준점을 고정합니다.
- 1시간봉 우선. 1시간봉 포지션이 없을 때 15분봉을 보조로 사용합니다. 시간봉별 하나씩, 최대 두 전략 포지션을 하나의 지갑으로 계산합니다.
- 15분봉 보유 중 1시간봉 신호가 나오면 진입·예상 청산 수수료를 뺀 순손익이 양수인 15분봉은 정리하고 1시간봉에 진입합니다. 손실 중이면 유지하면서 1시간봉에 진입합니다.
- 각 포지션은 다음 낮은 지지에서 최초와 같은 증거금을 한 번만 추가합니다. 기존 전략의 임의 가격 손절 없음 규칙을 유지했습니다.
- 1시간봉은 최초 증거금 세전 +100% 목표, +50% 도달 후 순이익 +25% 보호 및 추가 진입 금지. 추가 진입 후 수수료 포함 본절을 목표로 합니다.
- 15분봉은 최초 증거금 세전 +25% 목표, 추가 진입 후 수수료 포함 본절입니다. 100배에서 +25%는 가격 약 +0.25%이며 수수료 차감 후 25%가 아닙니다.
- 수수료는 진입·청산 각 명목금액의 0.05%, 유지증거금률은 단순 고정 0.4% 모델입니다. 실제 계정의 요율과 단계별 유지증거금을 조회한 값이 아닙니다.

## 실행과 관리

Linux, Node.js 22 이상, util-linux의 flock이 필요합니다. 외부 npm 패키지는 없습니다. Dockerfile에는 실행 환경을 포함했습니다.

```sh
npm test
node bot.cjs --once
node bot.cjs
node status.cjs
node control.cjs pause
node control.cjs resume
```

`--once`는 공개 데이터를 한 번 확인하고 종료합니다. `node bot.cjs`는 프로세스가 실행되는 동안 약 1초 간격으로 모의 운영합니다. Ctrl+C 또는 SIGTERM으로 정상 종료합니다.

기본 저장 폴더는 paper-data이며 PAPER_DATA_DIR로 바꿀 수 있습니다. status.cjs는 가상 지갑·평가자산·포지션·유지증거금·모의 청산가와 시세 상태를 표시합니다. status.cjs --check는 시세 지연·진입 정지·모의 청산 시 비정상 종료 코드로 모니터링에 사용할 수 있습니다.

pause는 새 진입과 추가 진입만 중단하고 기존 포지션의 모의 익절 판단은 계속합니다. resume는 다음 정상 시세 관측에서 모의 신규 진입을 다시 허용합니다. 실제 거래소 포지션을 읽거나 변경하는 명령이 아닙니다.

## 오류와 복구

- flock 운영체제 잠금으로 같은 폴더의 중복 프로세스를 막고, 프로세스가 죽으면 운영체제가 잠금을 해제합니다.
- 체크포인트는 임시 파일, fsync, 원자적 교체로 저장하고 이전 정상 파일은 .backup으로 보존합니다. 체크섬과 원장 합계가 맞지 않으면 시작하지 않습니다. 손상된 파일을 조용히 초기화하거나 백업으로 되돌려 재진입하지 않습니다.
- 재시작·시세 오류·5초 초과 시세 공백이 있으면 대기 주문을 취소하고 이전 시세를 초기화합니다. 열린 모의 포지션이 있으면 새 진입·추가 진입을 중지합니다. 기존 포지션이 모두 닫힌 뒤 정상 시세에서 자동 재개하며, 수동 pause는 resume 명령까지 유지합니다.
- 5초 넘게 오래된 시세, 역전된 호가, 미완성/누락 봉을 거부합니다. 봉 조회 도중 시세가 오래돼도 주문을 만들지 않습니다.
- 관측한 마크 가격에서 모의 계좌가 유지증거금을 침범하면 모의 포지션과 대기 주문을 정리한 전액 담보 손실 모델로 정지합니다. 실제 거래소 청산 체결을 재현한 것이 아닙니다.
- 체결·대기 주문 변화는 즉시 체크포인트를 남기고, 그 밖에는 약 10초 간격으로 저장합니다. 종료 시 최종 저장합니다. 관측 마크/평가 곡선은 최근 7일만 상태에 유지하고, 누적 최대낙폭·폐쇄 거래 원장은 보존합니다.
- v1 체크포인트는 v2가 자동으로 변환하지 않습니다. 기존 파일을 보존한 상태에서 검토해야 하며 가상 포지션을 무시하고 새 계좌를 덮어쓰지 않습니다.

## 검증

상태 복원 전후 동일 결과, 포지션 전환, 손실 포지션 유지, 짧은 익절, 미완성 봉 제외, 봉 누락·오래된 시세 거부, 원장 불일치와 체크포인트 손상 거부, 백업 보존, 중복 잠금, 관측 마크 청산 중단을 테스트합니다. validate-live.py는 실제 공개 데이터로 프로세스 중복 차단·pause/resume·정상 종료·재시작·상태 조회·손상 거부를 제한된 시간 동안 확인합니다. 이 단발 점검은 장기간 수익성 검증이 아닙니다.

100배·5%의 2026년 9월 원시 체결 백테스트는 별도 결과 폴더에 있습니다. 짧은 익절 병행안은 +31.23%, 최대낙폭 37.14%였습니다. 해당 월 한 번의 결과이며 다음 달 성과를 보장하지 않습니다.

## 서버 배포 준비

render.yaml은 기존 홍픽과 다른 `hongpick-btc-paper-100x5` 워커 한 개를 정의합니다. 0.5c-512mb, 싱가포르, 영구 디스크 1GB, 자동 배포 off, API 키 없음입니다. /var/data에 모든 상태를 저장하며 기본 Render 웹서비스나 홍픽의 설정을 바꾸지 않습니다. 별도 워커와 저장 디스크의 신규 비용 승인이 있어야 생성합니다.

Docker:

```sh
docker build -t hongpick-btc-paper .
docker run --rm -v btc-paper-state:/var/data hongpick-btc-paper node bot.cjs --once
docker run -d --name btc-paper --restart unless-stopped -v btc-paper-state:/var/data hongpick-btc-paper
docker exec --user node btc-paper node /app/status.cjs
docker exec --user node btc-paper node /app/control.cjs pause
docker exec --user node btc-paper node /app/control.cjs resume
```

영구 디스크가 있는 워커의 배포에는 잠깐의 중단이 생깁니다. 이 경우 위의 시세 공백 처리가 적용됩니다. Render 워커에는 HTTP health check가 없으므로 로그와 status.cjs로 관측해야 합니다. 이메일·메신저 알림은 연결하거나 발송하지 않았습니다.

## 실거래 전 남은 한계

현재 프로그램은 REST 호가를 약 1초마다 표본 관측합니다. 다음 관측 매수/매도호가에 가상 체결하므로 원시 체결 전체를 쓴 과거 백테스트와 체결 경로가 다릅니다. 관측 사이의 신호·가격·청산 위험을 놓칠 수 있습니다. 펀딩비, 호가 잔량, 실제 수량/가격 단위, 시장충격은 반영하지 않습니다.

실거래 엔진에는 WebSocket 재연결/누락 복구, 실제 포지션·미체결 주문 동기화, 주문 ID 중복 방지, 부분 체결·거절·타임아웃 처리, 실제 수수료·유지증거금·펀딩, 거래소에 남는 보호 주문 및 별도 위험 한도가 필요합니다. 이 프로그램을 그대로 실거래에 사용하면 안 됩니다. 현재 검증한 범위는 모의 운영입니다.
